# Design Knowledge Pilot — Alexander / CES

## Estado

**IMPLEMENTED LOCALLY / PILOT READY WITH LIMITATIONS.** This pilot operationalizes a small, traceable knowledge layer for architect-facing exploration. It does not ingest books, scans, images, or copyrighted text. It uses bibliographic metadata and structured, clearly bounded paraphrases only.

The pilot preserves the constitutional distinction:

> Influence is not authority. A pattern is not a requirement. Knowledge is not a decision.

## Pilot knowledge items

The catalog connects the following bounded concepts to the existing `DesignKnowledgeAgent`:

| Item | Role in exploration | Permitted effect |
|---|---|---|
| Relation between pattern and design process | THEORY → PROCESS | Formulate a design question or process direction |
| Public/private gradient | PATTERN → APPLICATION | Explore access, privacy and transition trade-offs |
| Oregon process/campus case | PRECEDENT_CONTEXT | Formulate phasing and spatial-relationship questions |
| PREVI experimental housing case | CASE → APPLICATION | Compare open-space/common-space questions |
| Houses Generated by Patterns case | CASE → PROCESS | Ask how a spatial relationship might become a visible alternative |

These items are scoped to the relevant `SpatialScope` values and carry explicit limitations. They do not create `Objective`, `Constraint`, `Recommendation`, `HumanReview`, or `Decision` records.

## Integration chain

```text
Human Intent
    ↓ explicit human confirmation
DesignKnowledgeAgent
    ↓ contextual matches + source provenance + limitations
GDI/P3/P6/P8 exploration
    ↓ deterministic spatial alternatives and perspectives
SpatialRepresentation / visual comparison
    ↓
Human Review and Decision authority remain separate
```

The existing `linkDesignKnowledge` flow now returns the matched items and their source records. The Guided Shell displays the match, epistemic type, source identifier, review state, license posture, and limitations. The existing deterministic generation and spatial representation are reused; no parallel alternative model is created.

## Runtime proof scope

The local proof covered:

1. natural-language intent interpretation;
2. explicit human adoption;
3. contextual knowledge matching;
4. source/provenance return;
5. controlled UPAO-001 derivative generation;
6. P3 spatial synthesis and representation;
7. bounded GDI candidate exploration;
8. multi-agent perspectives with `decision_created = false` and human confirmation required.

The proof is synthetic and deterministic. It demonstrates architecture and traceability, not real-world building performance, regulatory compliance, or empirical validity of any design theory.

## Deferred work

The following remain outside this pilot: full-text ingestion, automated book extraction, image/plan ingestion, rights clearance, translation of source content, regulatory cross-linking, domain-specific validation of patterns, empirical evaluation, and any automatic conversion of knowledge into a decision.
