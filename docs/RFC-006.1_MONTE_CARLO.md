# RFC-006.1 — Monte Carlo v1

**Estado:** IMPLEMENTED
**Base:** RFC-006 Simulation Contract
**Tipo:** Extensión analítica reproducible

## Objetivo

RFC-006.1 añade el método `monte_carlo_v1` al contrato de Simulation. El método ejecuta muestreos reproducibles sobre un parámetro declarado de una `Alternative` y devuelve estadísticos descriptivos. La ejecución es analítica, no decisoria.

## Entradas

La entrada es un objeto JSON con los siguientes campos:

| Campo | Requerido | Descripción |
|---|---:|---|
| `alternative_id` | Sí | Alternative existente en el proyecto activo. |
| `objective_id` | Sí | Objective existente asociado a la evaluación del resultado. |
| `parameter_name` | Sí | Nombre de un parámetro existente en la Alternative. |
| `parameter_distribution` | Sí | Distribución y parámetros numéricos. |
| `iterations` | No | Número de muestras; por defecto `1000`, con máximo `10000`. |
| `seed` | No | Semilla entera; por defecto `20260916`. |

Se admiten las distribuciones `NORMAL`, `UNIFORM` y `TRIANGULAR`. Sus parámetros son, respectivamente, `mean` y `std_dev`; `low` y `high`; o `low`, `mode` y `high`.

## Salidas

Una ejecución válida produce `Simulation.state=EXECUTED` y conserva en `outputs`:

- `mean`, `std_dev`, `min` y `max`;
- percentiles `p10`, `p50` y `p90`;
- `samples_count` y `convergence_check`;
- `seed`, `parameter_name`, `objective_id` y `alternative_id`;
- `provenance="SICL monte_carlo_v1"`.

La semilla forma parte de la salida y de la representación persistida. Por ello, repetir los mismos inputs y la misma semilla reproduce los mismos resultados y el mismo hash de evidencia. Cambiar la semilla cambia la ejecución reproducible y su hash.

## CLI

La forma general del contrato es:

```text
/SIMULATE RUN MONTE_CARLO monte_carlo_v1 <json_inputs>
```

También se admite la forma abreviada:

```text
/SIMULATE MONTE_CARLO <alternative_id> <objective_id> <parameter_name> <json_distribution> [iterations] [seed]
```

El catálogo se consulta con `/SIMULATE METHODS`. Las ejecuciones se consultan con `/SIMULATE LIST` y `/SIMULATE SHOW <simulation_id>`.

## HTTP v1

El endpoint canónico es:

```text
POST /v1/projects/{project_id}/simulations
```

El request utiliza `simulation_type="MONTE_CARLO"`, `method="monte_carlo_v1"` y `inputs` con la estructura definida arriba. Las respuestas usan el envelope HTTP v1 y conservan `contract_version`, `project_id` y `observed_version`. Los endpoints de listado y recuperación definidos en RFC-006 permanecen aplicables.

## Validación y errores

La ejecución devuelve `INSUFFICIENT` cuando falta la `Alternative` o el `Objective` requerido. Devuelve un error cuando el parámetro no existe, la distribución no es admitida, sus parámetros no son válidos o `iterations` está fuera del rango `1..10000`. No se permite una ejecución parcialmente definida.

## Invariantes constitucionales

Monte Carlo no crea `Decision`, `Recommendation`, `HumanReview`, `Evaluation` ni `Assumption`. No convierte una `Assumption` en un `Fact`. La Simulation resultante es append-only: una ejecución nueva crea un registro nuevo y no sustituye ejecuciones previas. La capacidad tampoco constituye certificación profesional, validación normativa ni decisión humana.

## Pruebas

La suite `tests/test_monte_carlo.py` verifica reproducibilidad, sensibilidad a la semilla, distribuciones admitidas, límites de iteraciones, validación de parámetros, persistencia tras reinicio, exposición HTTP y ausencia de decisiones o recomendaciones generadas automáticamente.

## Relación con RFC-006

RFC-006 define la entidad, el ciclo de vida, el hash y la superficie HTTP general de `Simulation`. RFC-006.1 añade únicamente el método `monte_carlo_v1` y sus reglas de entrada y salida; no altera la autoridad humana ni el contrato de persistencia.

## Estado y límites

La implementación es una capacidad analítica v1. No modela correlaciones entre parámetros, no realiza inferencia normativa y no sustituye una evaluación experta o una revisión humana.
